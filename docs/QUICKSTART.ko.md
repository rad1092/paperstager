# PaperStager 빠른 시작

PaperStager는 기존 PDF 묶음을 문서별로 나누고, 파일명을 직접 검토한 뒤 새 폴더에 내보내는 데스크톱 앱입니다. 원본 PDF는 읽기만 합니다. 앱 화면은 현재 영어이며, 이 안내에서는 화면의 버튼 이름을 그대로 사용합니다.

## 실행하기

[GitHub Releases](https://github.com/rad1092/paperstager/releases)에서 운영체제와 CPU에 맞는 압축 파일을 받아 **폴더 전체를** 풉니다. macOS에서는 `PaperStager.app`, Windows에서는 `PaperStager.exe`, Linux에서는 `./PaperStager`를 실행합니다. 실행 파일만 다른 곳으로 옮기면 필요한 라이브러리를 찾지 못할 수 있습니다. 배포본은 .NET 런타임을 포함합니다. Linux 실행 환경과 소스 빌드 방법은 [README](../README.md)를 참고하세요.

현재 배포본에는 macOS Developer ID 서명·Apple 공증과 Windows Authenticode 서명이 없습니다. 운영체제나 조직 보안 정책에서 실행을 차단할 수 있습니다. 배포 출처와 체크섬을 확인하고, 차단되는 환경에서는 조직이 승인한 방법이나 소스 빌드를 사용하세요. 보안 기능을 끄는 절차는 제공하지 않습니다.

## 먼저 예제 한 번 내보내기

1. **Try a synthetic example**을 누릅니다. 가상의 문서 두 개로 구성된 4페이지 PDF가 열립니다. 실제 개인정보나 청구서는 사용하지 않습니다.
2. **Boundaries & names**에서 1·3페이지가 각 문서의 시작인지 확인합니다. 4페이지는 회전된 예제입니다.
3. **Review proposed files →**를 누릅니다. 제안 파일명은 `2026-10-08_Northwind_INV-1001.pdf`, `2026-10-08_Meadow_INV-1002.pdf`입니다.
4. 각 문서의 페이지 범위와 필드 값을 확인합니다. 승인 상자 **I checked the boundaries, field values and all proposed paths.**를 선택합니다.
5. **Choose folder & export approved files…**를 눌러 저장할 상위 폴더를 선택합니다. 그 안에 `PaperStager-날짜-시간-식별자`라는 새 배치 폴더가 만들어집니다.
6. 결과 폴더에서 PDF 두 개와 `manifest.json`을 확인합니다. 이 기록에는 원본 경로·해시, 페이지 범위, 결과 파일명·해시와 건너뛴 문서의 사유가 들어 있습니다.

예제 원본은 운영체제 임시 폴더의 `paperstager-demo-…` 안에 만들어집니다. 예제 프로젝트를 나중에 다시 열려면 이 원본도 필요합니다. 임시 폴더는 영구 보관 장소가 아닙니다.

## 내 PDF로 작업하기

**1 · Import PDFs**에서 PDF를 창에 끌어 놓거나 **Choose PDFs…**를 누릅니다. 여러 파일을 함께 가져올 수 있습니다. 파일마다 최대 256 MiB, 5,000페이지이며 암호화된 PDF는 지원하지 않습니다. 주석·링크·양식·레이어·액션·첨부파일·비기본 UserUnit 등 안전한 분리 보존을 보장할 수 없는 PDF 구조는 가져오기와 내보내기에서 거부합니다. 오류에 표시된 구조를 확인하고, 필요하면 신뢰하는 PDF 편집기에서 평면화한 별도 사본을 만들고 확인한 뒤 가져오세요. 실패한 파일의 메시지를 확인하세요. 이미 가져온 파일을 프로젝트에서 제거해도 디스크의 원본은 삭제하지 않습니다.

**2 · Boundaries & names**에서 새 문서가 시작되는 페이지마다 **New document starts here**를 선택합니다. 첫 페이지는 항상 시작입니다. 예를 들어 1·3·6페이지를 선택하면 1–2, 3–5, 6–마지막 페이지가 각각 한 문서입니다. 페이지는 삭제하거나 재배열하지 않습니다. 미리보기는 한 번에 12페이지이며 **Previous pages / Next pages**로 이동합니다. 여러 PDF를 가져왔다면 위의 선택 상자에서 원본을 바꿉니다.

페이지의 **Read page text**로 추출된 텍스트를 확인합니다. 명명 규칙은 각 문서 묶음의 **첫 페이지**에 적용됩니다. 화면에서 다른 페이지 텍스트를 읽는 동작은 규칙의 대상 페이지를 바꾸지 않습니다.

이미지로만 된 PDF에는 추출할 텍스트가 없을 수 있습니다. 이 버전에는 OCR이 없습니다. 별도로 [NAPS2](https://www.naps2.com/) 같은 프로그램에서 검색 가능한 PDF를 만든 뒤 가져오거나, 검토 화면에서 값을 직접 입력하세요. 앱은 없는 날짜·금액·문서 번호를 추정하지 않습니다.

## 필드와 템플릿 만들기

원문에서 `Client:` 같은 라벨을 선택하고 **+ Add field from selected text**를 누릅니다. 만들어진 필드의 이름·종류·표현식을 편집합니다. 선택한 텍스트가 없어도 같은 버튼으로 행을 추가한 뒤 표현식을 직접 쓸 수 있습니다. 필드 이름은 `client`, `reference`, `date`처럼 영문자로 시작하고 영문·숫자·밑줄만 사용합니다. **필드 값과 최종 파일명에는 한글을 사용할 수 있습니다.**

| 필드 이름 | 종류 | 표현식 예 | 원문 예 |
| --- | --- | --- | --- |
| `client` | After label | `Client:` | `Client: Northwind` |
| `reference` | After label | `Reference:` | `Reference: INV-1001` |
| `date` | Regex | `Date:\s*(?<value>\d{4}-\d{2}-\d{2})` | `Date: 2026-10-08` |

**After label**은 줄 맨 앞의 라벨 다음, 같은 줄의 값을 읽습니다. 대소문자는 구분하지 않지만 같은 라벨이 여러 번 나오면 모호하므로 빈 값으로 남깁니다. **Regex**도 정확히 한 번 일치해야 하며, `value`라는 캡처 그룹이 있으면 그 값을 사용합니다. 없으면 첫 캡처 그룹, 그것도 없으면 일치한 전체 텍스트를 사용합니다. 정규식은 기본적으로 대소문자를 구분합니다. 줄을 넘는 값은 별도 표현식이 필요하며, 어려우면 검토 화면에서 직접 입력하세요.

파일명 템플릿에 `{date}_{client}_{reference}`를 입력합니다. `.pdf`는 없으면 자동으로 붙습니다. 기본 토큰도 사용할 수 있습니다.

| 토큰 | 값 |
| --- | --- |
| `{document}` | 문서 순번: `001`, `002` 등. 건너뛴 문서도 순번에 포함됩니다. |
| `{source}` | 확장자를 뺀 원본 파일명 |
| `{page}` / `{endpage}` | 문서의 첫 페이지 / 마지막 페이지 번호 |

템플릿은 **파일명만** 만듭니다. `/`, `\`, `..` 등을 사용해 하위 폴더나 상위 경로로 내보낼 수 없습니다. **Save template…**로 규칙을 JSON 파일에 저장하고 **Load template…**로 다시 사용할 수 있습니다. 템플릿에는 원본 PDF나 추출된 페이지 텍스트가 포함되지 않습니다.

## 검토·승인·저장

**3 · Review & export**에서 페이지 범위, 추출값, 최종 파일명을 확인합니다. 잘못된 값은 직접 고칩니다. 제외할 문서는 **Skip this document**를 선택하고 사유를 적습니다. 필수값 누락, 중복 이름, 운영체제에서 사용할 수 없는 문자가 있으면 내보내기가 차단됩니다. 중복에는 `{document}`를 추가하는 방법도 있습니다.

값을 바꾼 뒤 **Refresh plan after edits**를 눌러 최종 이름을 다시 확인합니다. 승인 상자를 선택한 다음 출력 상위 폴더를 고릅니다. 수정하면 승인은 해제되므로 현재 계획을 다시 검토해야 합니다. 경계를 바꾸어 문서의 페이지 범위가 달라지면 수동 입력과 건너뛰기 설정이 초기화될 수 있으므로 다시 확인하세요.

매번 새로운 배치 폴더를 만듭니다. 원본과 기존 출력 파일을 덮어쓰지 않습니다. **4 · Results**에서 결과 경로와 기록을 확인하고 **Review this batch again** 또는 **Import more PDFs**로 이어서 작업할 수 있습니다.

중간 작업은 **Save project…**로 `.json`에 저장합니다. 다시 실행한 뒤 **Open project…**로 엽니다. 자동 저장은 없습니다. 프로젝트에는 원본의 절대 경로, 해시, **추출된 전체 페이지 텍스트**, 경계, 수동 값과 규칙이 들어 있으므로 민감한 문서처럼 보관하세요. PDF 파일 자체는 포함하지 않습니다. 원본이 이동·변경되면 다시 가져와 검토해야 합니다. 승인은 저장되지 않습니다.

## 취소하거나 실패했을 때

가져오기·내보내기 중에는 **Cancel**로 중단을 요청할 수 있습니다. 처리 중 창을 닫으면 먼저 취소를 요청하므로 작업이 멈춘 뒤 다시 닫으세요. PDF 엔진의 현재 호출이 끝날 때까지 잠시 걸릴 수 있습니다. 저장하지 않은 프로젝트 변경은 닫을 때 버릴지 확인합니다.

내보내기는 먼저 `.paperstager-recovery-…` 폴더에 기록합니다. 모든 PDF가 준비된 뒤에만 최종 배치 이름으로 바뀝니다. 실패·취소·충돌 후 이 복구 폴더가 남았다면 **완료된 결과로 사용하지 마세요.** `recovery.json`을 확인하고, 원인을 해결한 뒤 저장한 프로젝트에서 다시 검토·승인하여 새 배치로 내보냅니다. 자동 재개나 복구 파일 가져오기는 없습니다. 디스크가 가득 찼거나 연결이 끊겼다면 최신 오류 기록도 저장되지 못했을 수 있습니다. 보관할 필요가 없는 복구 폴더는 내용을 확인한 뒤 사용자가 직접 삭제합니다.

더 자세한 범위와 실패 시 동작은 [제한사항](LIMITATIONS.md), 저장되는 정보는 [개인정보·오프라인 정책](PRIVACY.md)을 참고하세요.
